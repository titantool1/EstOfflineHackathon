# 다회용기 사진 확인 체험

`KR-CNP-GREEN-2026-A17` 미션 카드와 행동 상세에서 **사진으로 확인** 토글을 펼친다. 별도 페이지 이동은 없으며 접기/카드 이동 시 첨부와 진행 요청을 정리한다. 좌우 영역의 토글·입력 ID는 각각 독립이다. 로그인 회원이 JPG/PNG/WebP 한 장(최대 5MiB)을 선택하면 `/api/missions/photo-check`가 용기 유형·음식 가시성을 확인한다.

2026-09-18 container-boundary 실험의 S 지침·스키마, `gpt-5.4-mini-2026-03-17` low 설정을 사용한다. 일회용 포장/다른 대상 또는 빈 용기는 부적합, 다회용 제품+음식이 보이면 적합, 나머지는 확인 불가다. 화면은 모델의 자유로운 설명 대신 판정별 고정 안내를 표시한다.

사진 적합성만 판단하며 공식 실적·구매·소유·수행 시점 검증, 완료 사건·보상 저장은 하지 않는다. 파일명·사진·모델 원문은 앱 DB/디스크/로그에 저장하지 않고 요청 메모리에서 전달한다. 제공자에는 `store:false`를 요청하지만 제공자의 전체 로그 무보존을 뜻하지 않는다.

기존 Spring `/api/auth/me` 로그인과 Origin을 검사한다. MIME/base64/크기/시그니처를 확인하며 전체 이미지 디코딩 검사는 아니므로 손상된 이미지의 처리 실패는 오류 안내로 돌려준다. 회원별 동시1회·10초 간격, 서버 프로세스별 동시4회 제한이며 분산 할당량은 아니다. 서버30초/화면35초 제한이 있다. 기존 `OPENAI_API_KEY`, `SPRING_BASE_URL`을 사용하고 새 환경 변수·DB 이관은 없다.

기능 검사: `node --conditions=react-server --experimental-strip-types --test --test-isolation=none tests/mission-photo.test.ts`. 입력/인증/판정/제공자 오류/취소를 모델 대역으로 검사한다.

통합·배포 담당 확인: 실제 로그인 세션, 프록시의 새 API 경로와 base64 포함 최대 약7MiB 요청 허용, 실제 사진 선택/교체/실패 재시도·모바일 화면. 이번 기능 단위 검사와 과거 공개 사진16호출은 제품 전체 통합검증을 대신하지 않는다. 자동 보상은 별도 설계·검증 대상이다.
