# 대화 기능의 구현 위치

메시지 표시·입력·전송 상태를 둔다. LangGraph·모델·키·도구 조립은 `src/lib/server/ai`에 둔다. `/api/chat`은 기존 회원 세션을 확인하고 새 대화 runtime을 호출한다.

`src/app/chat/page.tsx`는 화면 진입점이고 `ChatPanel.tsx`와 `chat-client.ts`가 표시·입력·전송을 맡는다. 생성 중에는 입력과 새 상담 전환을 잠그고, 실패하면 입력을 보존한 채 새 상담을 안내한다.

브라우저는 `{conversationId?, clientSessionId?, clientRequestId, message}`를 같은 출처 JSON으로 보내고 `{conversationId, message}`를 공통 envelope로 받는다. 동일 출처는 요청 scheme과 표준 `Host`를 기준으로 확인하며 전달 host 헤더는 신뢰하지 않는다. DB와 외부 서비스에 직접 접근하지 않는다.

같은 탭의 새로고침·재진입에서는 sessionStorage의 무작위 `clientSessionId`로 GET `/api/chat`을 호출해 인증된 본인의 진행 중인 상담을 복원한다. 브라우저에는 대화 내용이나 개인 조건을 저장하지 않는다. 복원 응답은 표시용 메시지·진행 상태·남은 무활동 시간만 포함하며 모델 내부 상태와 조건 메모리는 반환하지 않는다. GET은 같은 출처의 Origin 또는 Sec-Fetch-Site와 회원 세션을 확인하고 no-store로 반환한다.

식별자가 있는 상담은 화면 연결이 끊겨도 이미 시작한 모델 작업을 기존85초 제한 안에서 마친다. 생성 중 복원은 같은 작업의 완료를 조회하며 질문을 다시 POST하지 않는다. 복원·완료 조회는90초 무활동 기한을 연장하지 않는다. 전송 중 통신 실패는 서버 상태를 다시 확인하고, 복원 조회 실패는 식별자를 보존한 채 재시도를 제공한다.

새상담·만료·로그인 확인 실패에서는 기존 상담을 복원하지 않는다. 종료 결과를 서버에서 확인할 수 있으면 실제 저장 상태를 안내하고, 상태가 없으면 이어갈 수 없음을 알린다. 현재 상담은 Next 프로세스 메모리에 있으므로 서버 재시작을 넘는 복원·장기 저장·여러 서버 사이 공유는 지원하지 않는다. 보내지 않은 입력문은 복원하지 않는다.
