# 회원·지도 요청 제한

단일 Spring/Next 프로세스에서 로그인·가입·장소/경로 작업의 호출량과 동시 실행을 제한한다. 초과 요청은 작업을 실행하기 전에 `429 RATE_LIMITED`와 초 단위 `Retry-After`를 반환한다. 회원 BFF는 안전한 숫자 Retry-After를 중계하고 회원/지도 화면은 재시도 안내를 표시한다. 자동 재전송은 하지 않는다.

## 초기 설정

아래 값은 실측 사용량으로 최적화한 값이 아니라 소규모 공유 환경의 초기 상한이다. 모든 창은60초다. 변경하려면 해당 서버의 실행 설정을 바꾸고 재시작한다.

| 대상 | 60초당 | 동시 실행 | 설정 |
| --- | --- | --- | --- |
| 로그인 계정별 실패 | 5 | 진행 중인 시도도 계정 슬롯에 포함 | Spring `eco.limits.account-failures` |
| 로그인 전체 | 60 | 4 | Spring `eco.limits.login-per-minute`, `eco.limits.login-concurrent` |
| 가입 전체 | 10 | 2 | Spring `eco.limits.signup-per-minute`, `eco.limits.signup-concurrent` |
| 장소 검색 전체 | 30 | 2 | Next `MAP_PLACES_PER_MINUTE`, `MAP_PLACES_CONCURRENT` |
| 경로 검색 전체 | 60 | 4 | Next `MAP_ROUTE_PER_MINUTE`, `MAP_ROUTE_CONCURRENT` |

Spring 값은 application properties나 `SPRING_APPLICATION_JSON`의 `eco.limits` 설정으로 전달한다. Next 값은 환경변수다. 양의 정수만 허용하며 잘못된 설정은 실행을 거부한다. 창 소진은 남은 초를, 동시 실행 소진은1초를 Retry-After로 안내하며 실제 실행 중 작업이 끝나야 슬롯이 열린다.

로그인 계정은 기존 서버 정규화 이메일을 사용한다. 실패 창 만료 후 복구하며 성공한 로그인은 해당 계정의 실패 수를 초기화한다. 없는 계정도 같은 실패 정책을 적용한다. 전체 한도는 성공·실패 모두 소비하고, 작업 종료 시 동시 실행 슬롯만 반환한다. 새 세션·QA 공유 쿠키·임의 forwarded 헤더는 한도를 초기화하거나 개별 사용자 식별자가 되지 않는다.

입력/CSRF 검증을 통과한 작업부터 횟수를 소비한다. 가입은 이메일/비밀번호 기본 검증 뒤 예약하고 나머지 업무 검증·중복 검사는 예약 안에서 수행한다. 오류·취소에도 동시 슬롯을 반환한다. 창이 바뀌어도 진행 중 작업의 동시 슬롯은 유지한다. 만료된 계정 실패 상태는 진행 중 시도가 없으면 다음 로그인 때 정리한다. 보관량은 전체 로그인 횟수·동시 실행 설정과 창 만료에 따라 제한되며, 별도 항목 수 제한으로 새 계정을 차단하거나 미만료 실패 상태를 지우지 않는다. 전체 로그인 상한을 크게 올리면 메모리 사용량과 정리 비용도 증가하므로 함께 검토한다.

## 요청 본문과 로그

회원 session BFF와 장소/경로 API의 요청 본문은16KiB까지 읽는다. 큰 요청은413, 읽기 시간 초과는504다. 회원은 기존10초 전체 proxy 제한에 본문 읽기를 포함하고 지도는 본문 읽기10초와 기존 upstream90초/15초를 적용한다. timeout은 실제 reader를 취소해 미완료 본문이 계속 기다리지 않게 한다.

로그인 실패·인증/CSRF 거부·횟수 제한 로그에는 요청 ID와 안전한 이벤트/상태만 남긴다. 비밀번호·쿠키·토큰·이메일·본문은 이 로그에 포함하지 않는다.

## 확인과 한계

프론트: `node --conditions=react-server --experimental-strip-types --test --test-isolation=none tests/request-limits.test.ts tests/account.test.ts tests/map-errors.test.ts`. Spring: `mvn test`. 기존 세션/소유권·동네 보안 회귀, 동시 예약·창 만료·성공 초기화·upstream 호출 중단·413/429/504·Retry-After 중계를 검사했다. 격리된 빌드 웹에서 회원/지도429와 미완료 요청10초 종료도 확인했다.

메모리 기반으로 재시작 때 초기화되고 여러 프로세스/서버의 한도를 합산하지 않는다. 익명 지도·가입의 전체 상한은 비용 보호이며 사용자별 공정성을 보장하지 않는다. 의도적 계정 잠금 유발 가능성도 남으므로 공개 사용 확대 시 신뢰할 수 있는 ingress 식별/분산 저장/추가 인증 정책을 다시 검토한다. 운영 공유 서비스 부하·실제 외부 제공자 호출·실제 DB 계정 변경은 이번 검사에 포함하지 않는다.
