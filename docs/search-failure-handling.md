# 검색 장애 시 재검색 중단

검색 서버/임베딩 오류가 나도 모델이 검색어만 바꾸어 반복하던 경로를 제한한다. `application/tool-failure-policy.ts`는 실제 오류 코드와 HTTP 상태로 그 턴의 도구 사용 종료 여부를 정한다. `conversation-flow.ts`는 오류를 원래 call_id의 function output으로 전달하고, 다음 응답에는 도구를 제공하지 않는다. OpenAI 어댑터도 `tool_choice: none`을 전송한다. 모델이 이 계약을 어기고 도구를 호출하면 실행 전에 거절한다.

최종 응답 한 번은 조회 실패 안내를 위해 남긴다. 오류를 결과0건/제도 없음으로 바꾸지 않도록 지시한다. 기존 provider의 function call을 정상적으로 마무리하고, 이미 채택한 상담 정정과 다음 턴의 정상 조회를 보존한다. 즉시 예외로 상담 전체를 닫는 동작으로 바꾸지 않는다.

- 턴 내 도구 종료: embedding 설정/통신/응답 오류, backend 설정/요청구성/통신/시간초과/응답 오류, 검색 upstream/partial/invalid response, DB unavailable, 알 수 없는 코드라도 HTTP5xx, 인증/접근401·403, 제한429.
- 유지: `no_results`의 표현 변경 검색, 로컬 JSON/인수 수정, 요청내용400 교정, 상세404 `not_found`. `INVALID_BACKEND_REQUEST`400은 고정된 서버 요청 구성 문제여서 예외적으로 도구 종료다.
- 취소는 기존 abort 경로를 따른다. 다른 미분류 예외와 모델 응답 실패도 기존 처리에 남는다. 같은 턴의 도구 종료 상태는 다음 턴에 이어지지 않는다.
- 분류 대상은 도구가 던진 오류다. 다른 세션에서 도구 묶음을 구현할 때 기존 오류를 임의의 성공 객체로 바꾸지 말고 code/status를 보존해야 한다.

검증은 실제 graph/runner와 모의 provider/HTTP에서 수행했다. 같은 재시도 대역의 장애 입력은 기존 검색3회/모델4회에서 검색1회/모델2회로 바뀌고, 정상0건 입력은 기존3회/4회를 유지했다. 이는 추가 호출 제거의 재현 결과이며 실제 모델 지연시간/p95 측정은 아니다. 최종 안내의 문구 정확성을 실제 모델로 평가한 결과로도 해석하지 않는다.

변경은 application의 실패 흐름 제어와 provider adapter의 도구 금지 요청이다. 회원 조건 저장/API/화면/모델 선택은 변경하지 않았다. 다른 호출 묶음·조건 저장 브랜치와 통합한 후 같은 장애/0건/정정/다음 턴 회귀 검사를 다시 실행한다.
