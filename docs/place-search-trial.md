# 장소 검색 API 소규모 시험

## 현재 상태

2026-09-16: 사용자가 주소 임베딩에 앞서 지도 API로 주변 실천 장소를 찾을 수 있는지 실제 시험을 요청했다. 비교 스크립트를 준비하고 dry-run과 키 미설정 경로를 실행했다. 이후 사용자가 REST/JavaScript 키를 설정했다. 실제 요청 1회와 원인 확인 요청 1회 모두 HTTP403이었다. 오류는 `NotAuthorizedError: disabled OPEN_MAP_AND_LOCAL service`로 카카오맵 서비스 비활성 상태다. 키 부족 상태는 해소됐고, 앱 관리의 카카오맵 사용 설정을 ON으로 바꾼 뒤 재개해야 한다. 검색 품질·반환 장소·좌표는 아직 미확인이다.

## 실행

저장소 `.env`에 `KAKAO_REST_API_KEY`를 설정하거나 같은 이름의 환경변수를 사용한다. 지도 화면용 JavaScript 키와 구분한다. 키 값은 로그나 Git에 넣지 않는다.

```bash
python3 scripts/place-search-trial.py --dry-run
python3 scripts/place-search-trial.py
# 다른 env 파일 사용
python3 scripts/place-search-trial.py --env-file /path/to/local.env
```

실제 조회는 최대18회이며 오류 발생 시 자동 재시도 없이 중지한다. 결과는 Git에서 제외된 `.local/place-search-trial/<UTC시각>/result.json`에 남긴다. 요청 파라미터·시각·HTTP 상태·결과 원문을 보존하고 인증 헤더는 기록하지 않는다. 앱·DB·모델은 변경하거나 호출하지 않는다.

## 입력과 비교

염창역·망원역·광주송정역 3곳에서 다음을 비교한다.

1. 자연어 문장 그대로: `<역 이름> 근처 페트병 수거점`.
2. 지하철역 검색으로 좌표 확인: 동일 이름의 역 후보가 정확히 하나일 때만 다음 조회. 여러 후보나 누락이면 확인 필요로 남긴다.
3. 기준 좌표 반경3km에서 `페트병 수거함`, `무인회수기`, `수퍼빈`, 일반 검색 대조용 `카페`를 각각 거리순 조회.

각 검색은 첫 페이지 최대15개만 확인하므로 전수 검색이나 재현율 측정이 아니다. 카테고리·이름·주소를 보고 실제 목적에 맞는 결과인지 사람이 검토한다. 0건과 API 실패를 구분한다. 좌표 수치와 직선거리를 확인하며 within_radius는 경계 오차50m를 허용한 보조 검사다. 결과가 있다고 실제 운영·수거 가능·혜택 적용이 입증되는 것은 아니다.

## 확인할 결론

자연어 입력과 시설명 정규화가 얼마나 다른 결과를 내는지, 수거기 같은 시설이 실제 검색되는지 확인한다. 누락된 시설은 기존 DB 자료와 대조할 후속 후보로 남긴다. 브라우저 지도 표시와 위치 권한 수집은 이번 시험 범위 밖이다.

API 계약 근거: [카카오 공식 REST API 문서](https://developers.kakao.com/docs/ko/kakaomap/rest-api). 실패 실행 근거는 `.local/place-search-trial/20260916T074010818291Z/result.json`, `20260916T074047710008Z/result.json`이다. 후자는 제한된 오류 메시지도 보존한다.
