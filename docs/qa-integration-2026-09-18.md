# QA 변경 통합 기준과 검사

기준 main62b1695 위에 배포된 QA 수정을 work/qa-integration-20260918로 고정했다. 새 프론트·로그인/복귀·프로필/동네·미션 추천/시작/완료/레벨/참여정보·지도/장소V13·상담 새로고침·매장검색을 포함한다. 메모리 후속 작업과 사진 재판정, 미션 문구의 추가 정리는 이번 고정 범위 밖이다.

## 소스 대조

배포 웹 qa-chat-places-v2의211파일과 백엔드 inline-v2의137파일이 동일하다. 통합본에만 기본 환경 예제1개가 있고, 백엔드 Dockerfile은 배포 검사 때 추가했던 Maven 캐시 복사 한 줄만 다르다. 기능 코드·자원·검사는 동일하다. 커밋 검사에서 region/validation.mjs의 파일 끝 빈 줄1개만 추가 정리했으며 실행 토큰은 바뀌지 않았다. 장소 이관 스크립트와1373행 입력을 함께 포함했고 V13 재생성 동일성도 확인했다.

## 검토와 한계

실제 diff에서 progress 프론트/서버 계약, owner/batch/item의 기록 분리, 인증 만료와 일반 오류 구분, 내부 복귀주소, 상담 복원 원점/소유권, 장소 검색 파라미터·쿠키 전달 범위를 대조했다. 이 통합 경계에서 새 차단 결함은 발견하지 않았다. 저장소 전체 구조·보안·정책 최신성 감사는 아니다.

매장검색 실제 모델과 공유HTTPS 확인은 같은 배포 소스의 기존 실행 근거를 사용했다. 이번에는 실제 모델·지도 SDK·사진을 재호출하지 않았다. 조건 메모리는 별도 수정 진행 중이다. 닫힌 용기 사진의 기존 오류는 사용자가 확인했고 이번 코드에서 보완한 것은 아니다. 미션 문구·조건관계 표시 역시 별도 조사 후속이다.

## Git과 실행 환경

별도 worktree의 검사한 커밋을 main으로 fast-forward하는 기준이다. main의 기존·동시 작업 파일을 보존하며 진행 중 수정은 미커밋으로 남긴다. 검사 컨테이너·DB·네트워크·시험용 키와 임시 worktree는 완료 후 제거하고 브랜치/커밋·로그·manifest는 보존한다. 공유 QA 서비스 교체와 원격 push는 이 통합 작업과 별도다.

자세한 원시 실행과 최종 반영: [작업대 근거](../../codex-harness-lab/evidence/eco-qa-merge-2026-09-18/README.md). 기능별 결과는 [QA 현황](qa-status-2026-09-18.md)을 따른다.

머지 직전 별도 작업의 qa-signup-home 배포와 AuthForm 가입 후 홈 이동1파일을 관측했다. 이번 검사는 그 이전에 고정한 매장검색v2 기준이다. 새 가입 경로는 공유 작업본에서 보존하고 해당 후속의 검사/커밋으로 구분한다. 이전 경로로 되돌리는 checkout은 하지 않는다.
