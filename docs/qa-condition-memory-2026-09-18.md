# 조건 메모리 고정 처리·QA 반영

2026-09-18. 프론트·백엔드 `qa-condition-memory-20260918`에 반영했다. 제도를 먼저 검색하지 않아도 지원하는 본인 조건을 상담 시작에 읽고, 매 턴 발화를 구조화한 뒤 코드가 검증·동일값 비교·메모리 반영을 수행한다. 조건 갱신 도구의 선택 여부에 기록을 맡기지 않는다.

확실한 생일과 대상이 모호한 가입을 함께 말하면 생일은 반영하고 가입만 되묻는다. ‘응’만으로 대상을 확정하지 않으며 서비스가 밝혀지면 해당 가입 정보만 반영한다. 실제 부정·모름·공개 거절을 구분한다. 답변/commit 실패는 기존 메모리를 유지한다. 상담 중 재사용하고 새 상담·90초 무활동 종료에서 DB에 저장하는 기존 정책은 유지한다. 다음 상담은 저장값을 다시 읽는다.

새 `GET /api/profile/conversation-context`는 인증된 본인만 대상으로 현재 카탈로그 매핑의 본인16항목을 구성한다. 새 가족·주택·차량을 추정하지 않는다. 기존 암호화 저장·baseline 충돌 검사·모름/거절의 저장 보류 정책과 DB 스키마는 그대로다. 매 턴 구조화 모델 호출1회가 추가된다. 자연어의 모든 표현이나 미지원 정보의 기록을 보장하는 것은 아니다.

프론트248검사·린트·타입·빌드, 실제 임시 PostgreSQL 백엔드112검사(skip0), 격리 후보8턴/20항목과 QA 보호 프록시 배포8턴/20항목을 확인했다. 합성 회원의 상담 중 DB 미변경→종료 저장→새 상담 재조회→미가입 정정과 모바일을 실제 모델/DB/화면으로 검증했다. 실제 답변에서 나온 내부 필드명 노출도 사람이 읽는 조건명으로 투영해 보완했다. 검사기의 스트림 수집 및 날짜/아니오 표현 비교 수정은 제품 결함과 구분해 기록했다.
